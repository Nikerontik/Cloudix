# Cloudix

P2P-мессенджер без серверов. Cloudix сам находит собеседников и позволяет переписываться,
обмениваться медиа, звонить и показывать экран — напрямую между устройствами. Никаких
аккаунтов и никакой регистрации: профиль лежит локально в SQLite.

**Работает в двух режимах:**

- **По локальной сети** — общий Wi-Fi/LAN. Собеседники находятся автоматически, настраивать
  нечего
- **Через интернет** — встроенная **сеть Cloudix**: один участник создаёт её по имени
  и паролю, остальные присоединяются по коду. Посредника нет, соединение идёт напрямую,
  поэтому у создателя сети должен быть достижимый извне порт (см.
  [раздел ниже](#сеть-cloudix-общение-через-интернет))

> ⚠️ Приложение сделано не самым опытным разработчиком. Возможны баги и нестабильная
> работа — спасибо за понимание!

**Платформы:** macOS (Intel + Apple Silicon) · Windows 10/11

---

## Возможности

**Сеть**
- 🔍 Автоматический поиск собеседников в локальной сети — без ручного ввода IP
- 🌐 Сеть Cloudix для общения через интернет: имя + пароль, код приглашения,
  сквозное шифрование. Без промежуточных серверов — хост принимает подключения сам

**Общение**
- 💬 Текстовые сообщения, фото и видео (до 25 МБ на вложение)
- 😀 Реакции на сообщения — свои и собеседника видны раздельно
- ✅ Статусы прочтения, индикатор «печатает…»
- 📮 Очередь доставки: сообщение, отправленное офлайн-собеседнику, уйдёт само, когда он
  появится в сети
- 📌 «Избранное» — локальные заметки, которые никуда не уходят
- 🚫 Блокировка пользователей

**Звонки**
- 📞 Аудио- и видеозвонки на WebRTC с раздельной регулировкой громкости
- 🖥 Демонстрация экрана до 1440p/60fps с настройками качества
- 🎛 Выбор микрофона и источника звука демонстрации — меняются **прямо во время звонка**
- 🪟 Окно звонка можно перетаскивать, мессенджер остаётся рабочим
- 📊 Живая статистика потока и диагностика соединения

**Интерфейс**
- 🎨 Три темы: тёмная, светлая и пастельно-розовая
- 🌍 Русский и английский языки
- 📶 Пинг до собеседника в реальном времени
- 🖼 Просмотр медиа на весь экран и сохранение на диск

## Установка

Собрать из исходников — см. [раздел ниже](#сборка-из-исходников). Готовые сборки, если они
опубликованы, лежат в [Releases](https://github.com/Nikerontik/Cloudix/releases).

**macOS.** Приложение подписано ad-hoc, поэтому при первом запуске Gatekeeper будет
возражать. Правый клик по `cloudix.app` → **Открыть** → **Открыть**. Либо разово:

```bash
xattr -dr com.apple.quarantine /путь/до/cloudix.app
```

При первом звонке система спросит доступ к микрофону и камере, при первой демонстрации —
к записи экрана. Разрешения выдаются в **Системные настройки → Конфиденциальность
и безопасность**.

**Windows.** Нужен рантайм **WebView2** — в Windows 11 и актуальной Windows 10 он уже
установлен. Если приложение не запускается, поставьте его
[с сайта Microsoft](https://developer.microsoft.com/microsoft-edge/webview2/).
При первом запуске брандмауэр спросит разрешение на доступ к сети — **разрешите**, иначе
собеседники не будут находиться, а звонки не соединятся.

## Сеть Cloudix (общение через интернет)

Если устройства не в одной локальной сети, включается встроенная сеть. Кнопка **сети** —
в левом нижнем углу, рядом с настройками и GitHub; когда сеть активна, она подсвечивается.

**Посредника нет.** Один из участников становится хостом: его копия Cloudix принимает
подключения остальных и пересылает трафик между ними. Поэтому к хосту нужно уметь
подключиться извне — это единственное требование.

### Кому что нужно

Есть два способа подключения, переключаются в панели сети:

| | Прямое | Через сервер-посредник |
|---|---|---|
| Белый IP у хоста | **нужен** | не нужен |
| Проброс TCP 47991 | **нужен** | не нужен |
| Работает при CGNAT | ❌ | ✅ |
| Нужен свой VPS | нет | да |

При **прямом** подключении требования есть только у хоста — участникам не нужно ничего,
исходящие подключения роутеры пропускают всегда. Если белого IP нет ни у кого, смотрите
[раздел про сервер-посредник](#через-сервер-посредник-при-cgnat).

### Шаг 1. Проверьте, годитесь ли вы в хосты

Откройте [2ip.ru](https://2ip.ru) и сравните показанный адрес с **WAN IP** в админке
своего роутера.

- **Совпали** → у вас белый IP, можно быть хостом
- **Разные** → провайдер держит вас за NAT (CGNAT). Хостом стать нельзя — никакие настройки
  роутера это не изменят. Признаки: WAN-адрес начинается с `10.`, `100.64`–`100.127`
  или `192.168`

При CGNAT: закажите у провайдера публичный IP (обычно 50–150 ₽/мес) либо пусть хостом
будет собеседник, у которого он есть.

### Шаг 2. Откройте порт

Cloudix пытается сделать это сам по **NAT-PMP**. Если роутер его поддерживает и он включён,
делать ничего не нужно — код приглашения появится сам, а в панели будет написано
«Порт открыт автоматически».

На **OpenWrt** NAT-PMP включается так:

```sh
opkg update && opkg install miniupnpd-nftables luci-app-upnp
uci set upnpd.config.enabled='1'
uci set upnpd.config.enable_natpmp='1'
uci commit upnpd && service miniupnpd enable && service miniupnpd restart
```

Если NAT-PMP недоступен — пробросьте порт вручную: **TCP 47991** на локальный IP
компьютера-хоста. Раздел в роутере называется *Port Forwarding*, *Virtual Server*
или *Переадресация портов*. Локальный IP стоит закрепить за компьютером через
DHCP-резервирование, иначе однажды он сменится и проброс отвалится.

Не забудьте разрешить входящие в брандмауэре самого компьютера. На Windows, в PowerShell
от администратора:

```powershell
New-NetFirewallRule -DisplayName "Cloudix" -Direction Inbound `
  -Protocol TCP -LocalPort 47991 -Action Allow -Profile Any
```

### Шаг 3. Создайте сеть

Кнопка сети → **Создать** → название и пароль (от 8 символов) → **Создать сеть**.

Появится **код приглашения** вида `CLDX-…`. Отправьте его собеседнику любым способом,
а **пароль передайте отдельно**.

> 🔐 Код приглашения намеренно **не содержит пароль**: он несёт только название сети
> и адрес хоста. Перехваченный или переотправленный код сам по себе бесполезен.

Если кода нет — значит внешний адрес определить не удалось. Пробросьте порт вручную
и передайте собеседнику свой публичный IP.

### Шаг 4. Присоединитесь

Кнопка сети → **Присоединиться** → вставьте код и введите пароль.

Либо вручную, если кода нет: **По адресу вручную** → название сети, адрес хоста
(`203.0.113.7` — порт подставится сам) и пароль.

После подключения участники появятся во вкладке **«В сети»** с пометкой
«через сеть Cloudix». Дальше всё как обычно: чаты, звонки, демонстрация экрана.

### Проверка, если не подключается

```powershell
netstat -ano | findstr :47991      # Windows: Cloudix слушает порт?
```

Затем на [canyouseeme.org](https://canyouseeme.org) проверьте порт `47991` при созданной
сети. «Success» — снаружи достучаться можно, дело не в роутере.

### Через сервер-посредник (при CGNAT)

Если ни у кого нет белого IP — а при CGNAT его и не получить — прямое подключение
невозможно. Тогда обе стороны подключаются **наружу** к серверу-посреднику, и он сводит
их вместе.

**Сервер вы запускаете сами и указываете его адрес в приложении.** В код он не зашит —
никакого «сервера Cloudix», через который шёл бы ваш трафик, не существует.

**1. Соберите и запустите ретранслятор** на любой машине с белым IP (подойдёт самый
дешёвый VPS):

```bash
go build -o cloudix-relay ./cmd/cloudix-relay
./cloudix-relay -addr :47992 -token "придумайте-длинный-ключ"
```

Откройте на сервере входящий TCP 47992. Как служба systemd:

```ini
[Unit]
Description=Cloudix relay
After=network.target

[Service]
ExecStart=/opt/cloudix/cloudix-relay -addr :47992 -token ПРИДУМАННЫЙ_КЛЮЧ
Restart=always
User=cloudix

[Install]
WantedBy=multi-user.target
```

**2. В приложении** — кнопка сети → переключатель **«Через сервер»** → впишите адрес
и ключ доступа. Настройки запоминаются, вводить их каждый раз не нужно.

**3. Дальше как обычно:** один создаёт сеть (имя + пароль), остальные присоединяются,
указав **то же имя сети** и тот же сервер. Проброс портов не нужен никому.

#### Что видит и чего не может сервер

- Видит только **обезличенный идентификатор комнаты** — хеш, из которого нельзя
  восстановить ни название сети, ни пароль
- **Не участвует в аутентификации** и не имеет ключа сети — присоединиться к вашей сети
  он не может
- **Пересылает уже зашифрованные байты.** Сквозное шифрование между участниками
  работает поверх него ровно так же, как при прямом подключении: прочитать или подменить
  переписку сервер не может, даже будучи скомпрометированным
- Может только **отказать в пересылке** — то есть уронить связь, но не подслушать

Ключ доступа (`-token`) ограничивает, кто вообще может пользоваться вашим сервером.
Он защищает вашу пропускную способность, **а не переписку** — её защищает пароль сети.

### Как это защищено

- Пароль **никогда не покидает устройство**: из него через Argon2id выводится ключ сети,
  а в сеть уходит только обезличенный идентификатор — по нему нельзя восстановить
  ни название, ни пароль
- Знание пароля проверяется неявно: ключ сети вмешивается в вывод сессионного ключа,
  поэтому с неверным паролем просто не расшифровывается первый же кадр. Обходить нечего
- Трафик между участниками шифруется сквозным ключом (X25519 + XChaCha20-Poly1305):
  **хост пересылает данные, но прочитать их не может** — у него нет ни одного из приватных
  ключей
- Ключи участников запоминаются при первой встрече. Если ключ вдруг сменился, участник
  отвергается: именно так выглядела бы попытка подмены. Отпечаток своего ключа виден
  в панели сети — сверьте его с собеседником голосом
- Звонки и демонстрация идут напрямую между участниками (WebRTC), через хост проходит
  только сигналинг

> ⚠️ Это оверлей **для трафика Cloudix, а не системный VPN**: игры и другие программы
> через него не пойдут. Полноценный виртуальный адаптер требует подписанного драйвера
> ядра на Windows и специального entitlement от Apple на macOS — их нельзя поставить
> с самоподписанным приложением.

## Как это работает по локальной сети

Оба устройства в одном Wi-Fi/LAN — либо в общем туннеле вроде RadminVPN, если он у вас
уже используется. Настраивать нечего:

1. Запустите Cloudix на обоих устройствах и создайте профиль
2. Откройте вкладку **«В сети»** — собеседник появится там сам
3. Нажмите на него, чтобы начать чат

Если собеседник не появился — кнопка **обновления** рядом с переключателем темы
пересоздаёт сетевые сокеты и заново сканирует сеть. Это помогает после смены Wi-Fi,
выхода из сна или подключения VPN.

## Звук демонстрации экрана на macOS

Windows отдаёт системный звук сам — при запуске демонстрации просто отметьте галочку
в диалоге выбора окна.

**macOS так не умеет:** система принципиально не отдаёт приложениям системный звук, это
ограничение платформы, а не Cloudix. Обходится один раз через виртуальный аудиодрайвер.

### 1. Установите BlackHole

```bash
brew install blackhole-2ch
```

Без Homebrew — установщик с [existential.audio/blackhole](https://existential.audio/blackhole/).
После установки **перезагрузите Mac** — это драйвер уровня ядра.

### 2. Создайте устройство с несколькими выходами

Нужно, чтобы звук шёл одновременно в ваши колонки (вы слышите) и в BlackHole (слышит
собеседник).

1. Откройте **Настройка Audio-MIDI** (Audio MIDI Setup) — найдётся через Spotlight
2. Слева внизу **«+»** → **Создать устройство с несколькими выходами**
3. Отметьте галочками **свои колонки/наушники** и **BlackHole 2ch**
4. Ваши колонки должны быть **первыми** в списке — это главное устройство
5. Напротив BlackHole поставьте галку в столбце **«Коррекция сдвига»**

### 3. Переключите вывод системы

**Системные настройки → Звук → Выход** → выберите созданное устройство.

> ⚠️ У устройства с несколькими выходами не работают клавиши громкости на клавиатуре.
> Регулируйте громкость внутри приложения (плеер, браузер). Когда демонстрация не нужна —
> верните обычный выход.

### 4. Выберите источник в Cloudix

**Настройки → Демонстрация экрана → Звук демонстрации → BlackHole 2ch**

Готово. Звук уйдёт собеседнику отдельной дорожкой, и он сможет регулировать её громкость
независимо от голоса — прямо в окне просмотра демонстрации.

> Если список устройств выглядит безымянным, сделайте один звонок: macOS начинает отдавать
> названия аудиоустройств только после выдачи доступа к микрофону.

## Настройки демонстрации экрана

**Настройки → Демонстрация экрана.** Всё применяется сразу, включая уже идущую
демонстрацию.

| Параметр | Значения | Что делает |
|---|---|---|
| Разрешение | 720p / 1080p / 1440p | Ограничивает картинку на стороне кодировщика |
| Частота кадров | 15 / 30 / 60 | Потолок FPS |
| Приоритет | Сбалансированно / Чёткость / Плавность | Чем жертвовать при нехватке ресурсов |
| Битрейт | 2–30 Мбит/с | Потолок потока |
| Звук демонстрации | Системный / устройство / без звука | См. раздел выше |

**Если картинка рассыпается на квадраты** — поднимите битрейт. **Если проседает FPS на
движении** — поставьте «Плавность» или снизьте разрешение. Хороший компромисс для текста
и кода: **1080p / 30 fps / Чёткость**. Реальные цифры потока видны в шапке окна
демонстрации — по ним понятно, куда упирается.

## Модель безопасности

Гарантии разные в зависимости от режима — это важно понимать.

**По локальной сети** Cloudix рассчитан на **доверенную сеть** (домашний LAN или частный
VPN):

- Медиапоток звонков и демонстрации шифруется (WebRTC / DTLS-SRTP)
- Текстовые сообщения, медиа и сигналинг передаются **в открытом виде и не подписываются** —
  любой в той же сети технически может отправить сообщение от чужого имени
- **Не используйте этот режим в публичных или недоверенных сетях**

**Через сеть Cloudix** всё строже: трафик между участниками зашифрован сквозным ключом,
отправитель подтверждён криптографически (подделать его нельзя, не имея приватного ключа),
а хост не может прочитать то, что пересылает. Подробности — в
[разделе про сеть](#как-это-защищено).

Во всех режимах данные хранятся только локально, наружу ничего не уходит.

## Сборка из исходников

**Требования:** [Go](https://go.dev/dl/) 1.25+ · [Node.js](https://nodejs.org/) 18+ ·
[Wails CLI v2](https://wails.io/docs/gettingstarted/installation)

```bash
go install github.com/wailsapp/wails/v2/cmd/wails@latest
```

```bash
wails dev                               # разработка с горячей перезагрузкой

wails build -platform darwin/universal  # -> build/bin/cloudix.app
wails build -platform windows/amd64     # -> build/bin/cloudix.exe
```

> Кросс-компиляция из macOS в Windows в Wails поддерживается ограниченно. Для релизных
> `.exe` собирайте на Windows или в CI — в репозитории есть готовый workflow
> `.github/workflows/build.yml` с матрицей `windows-latest` / `macos-latest`.

### Два экземпляра на одной машине

Для проверки переписки удобно запустить две копии с разными базами:

```bash
BIN=build/bin/cloudix.app/Contents/MacOS/cloudix
CLOUDIX_INSTANCE=a "$BIN" &
CLOUDIX_INSTANCE=b "$BIN" &
```

Сообщения и медиа так работают. **Звонки между двумя копиями на одной машине не
соединяются** — обе разрешаются в один IP, и ICE не проходит. Звонки проверяются только
на двух разных устройствах.

## Где лежат данные

Профиль, чаты и сообщения — в одном SQLite-файле:

| ОС | Путь |
|---|---|
| macOS | `~/Library/Application Support/Cloudix/cloudix.db` |
| Windows | `%APPDATA%\Cloudix\cloudix.db` |

Папку можно открыть прямо из приложения: **Настройки → О приложении → Открыть**. Там же
видна версия сборки — полезно, чтобы убедиться, что на обоих устройствах одна и та же.

Кнопка **«Выйти»** в настройках удаляет локальный профиль вместе со всей перепиской
безвозвратно.

## Технологии

- **Бэкенд:** Go, [Wails v2](https://wails.io), SQLite (`modernc.org/sqlite`, без cgo)
- **Фронтенд:** React 18, Vite, Framer Motion
- **Обнаружение пиров:** UDP multicast `239.255.42.99:47990` + unicast-фолбэк для VPN
- **Сообщения:** построчный JSON поверх TCP
- **Звонки и демонстрация:** WebRTC, сигналинг через тот же TCP-транспорт, STUN без TURN

```
Cloudix/
├── backend/
│   ├── app/        # Bound-методы для фронтенда, роутер входящих пакетов
│   ├── models/     # Общие структуры, типы wire-протокола
│   ├── storage/    # SQLite
│   ├── transport/  # TCP-транспорт
│   └── discovery/  # UDP multicast + unicast
```

## Диагностика

**Собеседник не находится**
- Убедитесь, что оба устройства в одной сети / подключены к одному VPN
- Нажмите кнопку обновления рядом с переключателем темы
- На Windows проверьте, что брандмауэр не блокирует Cloudix
- В гостевых и корпоративных Wi-Fi часто включена изоляция клиентов — она блокирует
  любую связь между устройствами

**Звонок не соединяется**
- В окне звонка разверните **«Диагностика»** — там видны состояния ICE, счётчики
  кандидатов и выбранная пара
- Убедитесь, что на обоих устройствах **одна и та же версия** (Настройки → О приложении)

**Демонстрация лагает** — см. раздел про настройки выше.
